# ETEL Delivery — Customer App: Premium Metallic Gold Retone

## Scope

This pass audited the existing production Customer app (`delivery/customer.html`,
`delivery/css/customer-v5.css`, `delivery/js/customer.js`, `delivery/js/core.js` via
`customer-bundle.js`) against the client's supplied reference screenshots and applied a
visual retone to the client's specified palette:

- Background: `#07070A` / Surface: `#101014` / Surface 2: `#15151B`
- Gold: `#D4AF37` / Gold highlight: `#F0CA58`
- Text: `#F7F1DF` / Muted: `#9D998D`
- Success: `#32C875` / Danger: `#EF4444`

**No backend functionality, API calls, authentication, payment integrations, Google
Maps/Places, or PWA/service-worker registration logic were removed or replaced.** This
was a visual-layer change only, per the "sit on top of existing production
functionality" requirement.

## Audit findings

The Customer app already implements essentially every screen requested in the brief —
home feed with promos/quick-access/categories, restaurant/shop scroll, item grid, item
detail modal, cart drawer, delivery-tier selector, address autocomplete (Google
Places), gate/entrance photo upload, recipient fields, multi-method payment (Telebirr,
ኢE Pay/Wallet, Cash, Abysinia, CBE), checkout, real-time order tracking (SSE), courier
QR delivery confirmation, star rating, issue reporting, order history, favorites,
messages, saved addresses, referrals, settings, wallet/payments, and profile — all
wired to real backend endpoints (`api/boot.php` actions) in `js/customer.js`, `js/core.js`.

The one real defect found: several server-rendered UI fragments (cart line items, the
delivery-tier picker, the payment-method picker, order-history cards, the rating modal,
and the issue-report modal) were hardcoded with **light-mode inline styles** (`#fff`
backgrounds, `#1a1a2e` near-black text, `#ddd` borders) left over from an earlier theme,
while the surrounding app (header, promos, cart drawer chrome, bottom nav) is fully dark
gold-themed. In the two modals specifically (`openRating`, `openOrderIssue`), heading
text was rendered as `#1a1a2e` (near-black) inside `custShowModal()`'s dark charcoal box
(`linear-gradient(180deg,#171006,#0a0703)`) — meaning that text was effectively
invisible in production. This is fixed as part of this change.

## Files changed

- `delivery/css/customer-v5.css` — retoned all CSS custom-property tokens and hardcoded
  `rgba(255,215,0,…)` / `#FFD700` family values to the client's metallic-gold/charcoal
  palette. Added `--muted`, `--success`, `--danger` tokens matching the spec. No
  selectors, class names, or layout rules were altered — cascading token change only.
- `delivery/js/customer.js` — retoned inline styles generated by `renderCartDrawer()`,
  `tierOptionBtn()`, `paymentOptionBtn()`, `highlightPaymentBtn()`, the order-history
  card renderer, `openRating()`'s modal body, and `openOrderIssue()`'s modal body from
  the old light-mode/legacy-gold (`#fff`, `#1a1a2e`, `#ddd`, `#C9A961`, `#8B6E3A`)
  literals to the dark charcoal/metallic-gold equivalents. No function signatures, API
  calls, or control flow changed — inline `style` strings only.
- `delivery/sw.js` — bumped `CACHE_NAME` (`etel-v55` → `etel-v56`) so the service
  worker's cache-first strategy picks up the new CSS/JS on next load, per this
  codebase's existing cache-busting convention.
- `delivery/customer.html` — bumped the `?v=` cache-busting query params on
  `css/customer-v5.css` (5.3 → 5.4) and `js/customer.js` (4.23 → 4.24).

## APIs / functionality preserved

- Authentication (`Auth` from `core.js`, bundled via `customer-bundle.js`) — untouched.
- Order placement/payment (`placeOrder`, `placeOrderThenPay`, `placeOrderThenBank`,
  Telebirr polling, bank reference flow) — untouched, only the payment-picker's `style`
  strings changed.
- Delivery pricing/tiers (`loadDeliveryTiers`, `getTierMultiplier`, `getDeliveryFee`,
  `getEstimatedTime`) — untouched; tier fees/ETAs still come from the backend
  (`_deliveryTiers`), never hardcoded.
- Google Places/GPS (`initDeliveryAutocomplete`, `getMyLocation`, zone detection) —
  untouched.
- Gate/entrance photo upload — untouched, only the button's idle-state background color
  changed.
- Order tracking (`startOrderSSE`), courier QR delivery confirmation
  (`openCourierQRScanner`, `_custQrExtractOrderId`), rating (`openRating`,
  `submitRating`), issue reporting (`openOrderIssue`, `submitOrderIssue`) — untouched
  logic; only their rendered `style` strings changed.
- PWA manifest/service worker — untouched apart from the required cache-name bump.

## Testing performed

- `node --check delivery/js/customer.js` — syntax valid.
- Brace-balance check on `delivery/css/customer-v5.css` — balanced.
- Manual grep sweep confirming zero remaining occurrences of the old vivid-yellow
  (`#FFD700`, `rgba(255,215,0,…)`) and legacy light-mode (`#1a1a2e`, `#C9A961`,
  `#8B6E3A`) literals in the changed files.
- Could not run this in an actual mobile/desktop browser from this sandbox (no live
  server/browser available here) — **a visual pass in a real browser against the
  reference screenshots is still recommended before this is considered fully verified**,
  per this session's testing limitations.

## Remaining limitations / not done in this pass

- A few secondary buttons ("Rate this order", "Report an issue" on order-history cards,
  the wallet-payment "Open ኢE Pay Wallet" link) intentionally kept a white/light button
  face with colored text — this is a legible, common "outlined light button on dark
  card" pattern and wasn't flagged as broken, but could be further retoned to fully
  match the reference screenshots' all-dark card treatment if desired.
- The legacy, unused `delivery/css/customer.css` (not referenced by `customer.html`,
  which loads `customer-v5.css`) was left untouched — out of scope since it isn't live.
- No new screens, endpoints, or promotions were invented; all promotional copy, prices,
  and delivery-tier data continue to come from the existing configured
  backend/hardcoded-in-markup values already present before this change.
- Full 40-item manual QA checklist from the brief was not executable in this sandbox
  (no browser); please smoke-test the live app after deploy, particularly the cart
  drawer, checkout, rating, and issue-report flows called out above.
