# ETEL Delivery - hands-on audit (2026-11-08)

Done by reading code and testing a running copy on a throwaway database. Nothing here is an AI guess: each line says what was tried.

## What was checked and how
| Area | What was done | Result |
|---|---|---|
| Who may do admin things | Called all **260** admin-style actions with no sign-in, and again as a plain customer | Every one was refused, except the admin login itself (expected) and four 2FA set-up actions (see F5) |
| Reading other people's orders | Read the ownership checks on order, cancel, rate and courier actions | Each checks the order belongs to the caller (customer, courier or shop) |
| Passwords and tokens | Read sign-in, token and logout code | bcrypt hashes; HMAC tokens, 7 days, revoked at once by a version bump; sign-in and sign-up are rate limited |
| Payment callbacks | Read the Telebirr and Chapa callbacks | Both reject a missing or wrong signature using a timing-safe compare |
| Pictures and papers | Read `upload.php` and the uploads folder rules | Real image type check, 5 MB limit, nothing in uploads can run as code or be shown as a page; papers use signed private links |
| Browser requests | Read the cross-site rules | Tokens are sent in a header (not a cookie), so classic cross-site request forgery does not apply. The risk to watch is script injection; the CI sink check covers it |
| Money | Looked for balance changes outside a locked transaction | Wallet code uses row locks (`FOR UPDATE`); package price comes from the server and ignores what the app sends |
| Public script files | Opened 20 `api/*.php` files with no sign-in | Cron, backup, diagnostics and old debug scripts need a key or are retired; see F3, F4, F6 |

## Findings
| # | Severity | Finding | Status |
|---|---|---|---|
| F1 | High | **The Code Audit could not find anything.** "Run Audit Now" sent only 42,000 characters (about 10 files, 4,500 characters each) of a 185,000-line project, files in alphabetical order. The AI then reported "no issues" and A-, which is why that report is not trustworthy. | Fixed: about 220,000 characters, 14,000 per file, sign-in, token, money, upload and admin files first |
| F2 | High | **The Code Audit could send `.env` to an outside AI service.** The scan explicitly allowed `.env` files (database password, token secret, payment keys). It was only the size limit that kept them out in practice. | Fixed: environment files, keys and certificates are never sent, and secret-looking values typed into code are blanked. Covered by `tests/audit_agent_test.php` |
| F3 | Low | `migrate.php` lists every database change (names, dates, counts) to anyone who opens it. Applying changes needs an admin. | Open: limit the list to admins |
| F4 | Low | `health.php` and `etel-os.php` are public and show disk space, database status and version numbers. | Open: fine for a status monitor, but trim the details if you do not need them |
| F5 | Low | Four `admin_2fa_*` actions work for any signed-in role, so a customer can start two-step set-up on their own account. It only affects their own account. | Open |
| F6 | Low | `chat.php` answers 500 instead of 401 when called with no sign-in. | Open |
| F7 | Medium | About 119 places add database columns while a request is running. A column change cannot be undone, so a failure half way can leave a half-finished save. The new code in this project adds columns before the transaction starts, which is the safe pattern. | Open: move the older ones into migrations over time |
| F8 | Medium | Three files are very large (`RideController.php` 5,168 lines, `boot.php` 2,807, `AdminController.php` 2,454), so every change to them is risky and slow to review. | Open: split by feature when you next change them |
| F9 | Low | The allowed-origins list used in production still includes `http://localhost` and `http://127.0.0.1`. | Open |

## Not checked (needs another pass)
Telebirr and Chapa payment flows end to end with real sandboxes, the Equb and equity modules, ride dispatch under heavy load, the Courier, Driver and Ride app bundles, and the real production server settings.

## Correction
An earlier note said no cross-site request forgery protection was found. That was wrong for this system: it uses header tokens, not cookies, so it does not need it.
