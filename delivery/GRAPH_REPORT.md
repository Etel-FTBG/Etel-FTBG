# GRAPH_REPORT.md — ETEL Delivery / Ride API

Manually traced from `delivery.zip` (api/boot.php routing table + each
controller's `require` statements). Not generated by Graphify — this
mirrors the kind of report it produces, built by hand from the actual
source.

Scope: `delivery/api/`. Frontend bundles, migrations, and uploads were
not traced in this pass.

---

## 1. Entry point

```
api.php
  └─ require boot.php
```

`boot.php` is a single `switch ($action)` block. Each `case` requires
exactly one controller file on demand — controllers are **not**
pre-loaded. This is the fact that mattered for the 500-error fix below.

## 3. Shared lib/ (edges — the cross-cutting layer)

`boot.php` does not auto-load `api/lib/`. Every controller that needs
something from it must `require_once` it directly.

| lib file | Required by | Risk |
|---|---|---|
| `lib/schema_helpers.php` | `RideController.php`, `AdminController.php` | **Was the 500-error bug.** `rides_add_missing_cols()` originally lived inside `RideController.php` only; `AdminController.php` called it without loading it. Fixed 2026-08-19 by extracting it into this shared file, required by both. |
| `lib/ride_fare.php` | `RideController.php`, `AdminController.php`, `AgentController.php` | Same shape of risk — already patched once before (see `AdminController.php` header comment re: `rides_default_peak_windows()`). Any new function added here must be checked against all three callers. |
| `lib/delivery_pricing.php` | `AgentController.php` only | Single-owner, low risk. |
| `lib/delivery_order_core.php` | `OrderController.php`, `AgentController.php` | Two callers — worth a grep-check before editing, same discipline as the two above. |

**Rule derived from this graph:** any function that more than one
controller calls must live in `lib/` and be `require_once`'d by name in
every calling controller — never assumed to be available because
"some other controller probably loaded it first." Load order in
`boot.php` is per-action, not global.

## 5. Suggested scope split for future sessions

Matches the earlier session-scoping recommendation, grounded in the
edges above:

1. **Ride core** — `RideController.php` alone (largest file, 159K)
2. **Admin dashboard** — `AdminController.php` alone
3. **Delivery & Order flow** — `OrderController.php` + `ServiceGiverController.php`
4. **Agent/API layer** — `AgentController.php`
5. **Auth & Push** — `AuthController.php` + `PushController.php` (light, bundle together)
6. **Shared lib/ changes** — its own session whenever touching `schema_helpers.php`, `ride_fare.php`, or `delivery_order_core.php`; grep every calling controller first
7. **Frontend bundles** — split by which HTML page they power, kept separate from backend PHP sessions
